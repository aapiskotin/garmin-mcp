# Планирование подготовки к беговым мероприятиям

Статус: локальный планировщик реализован; управляемая публикация в Garmin остаётся следующим этапом.
Дата: 2026-10-25.

Документ расширяет [базовую спецификацию](garmin-app.md). Её требования
к локальному запуску, SQLite, работе с Garmin по запросу, происхождению
данных и резервному копированию сохраняются. Новый интерфейс планирования
разрешает локальное редактирование; существующие lookup UI и Datasette
остаются доступными только для чтения.

## 1. Назначение и границы

- Готовить пользователя к одному главному беговому мероприятию в рамках
  цикла подготовки; поддерживать дополнительные старты внутри этого цикла.
- Сохранять цели, план, фактическое выполнение, обратную связь и причины
  решений независимо от истории чатов.
- Поддерживать согласованную работу через агента и локальный веб-интерфейс.
- Использовать существующее приложение, SQLite и Docker Compose.
  Отдельные сервисы, облачная база и очередь задач не требуются.
- Анализ и предложения по подготовке принадлежат агенту. Приложение
  проверяет и сохраняет данные, рассчитывает явные показатели и показывает
  изменения. Оно не изменяет план самостоятельно по оценке Garmin.
- Не включать в первую версию многопользовательский режим, социальные
  функции, уведомления, автоматический подбор соревнований и фоновую
  адаптацию плана.
- Конкретный главный старт, дата, результат и доступность пользователя
  заполняются при создании цикла; спецификация не задаёт их за пользователя.

## 2. Основные сценарии

1. Создать цикл: указать главный старт, цель, период подготовки,
   доступные дни и ограничения; сохранить начальную версию плана.
2. Посмотреть сегодняшний день и неделю: задания, их назначение,
   доступные варианты, выполнение и актуальность данных Garmin.
3. После занятия загрузить данные Garmin по запросу либо вручную
   отметить выполнение; записать усилие, самочувствие и комментарий.
4. Провести обзор недели: сравнить план и факт, объяснить отклонения,
   подготовить и применить изменения будущих занятий.
5. Добавить дополнительный старт: определить его роль, показать влияние
   на окружающие занятия и сохранить изменения новой версией.
6. Учесть поездку, изменение расписания или самочувствия: сохранить
   ограничение с периодом действия и пересмотреть затронутые занятия.
7. Завершить или отменить цикл, сохранив его историю; для следующего
   главного старта создать новый цикл.

## 3. Организация плана

- Иерархия: цикл → этапы → недели → занятия. Мероприятия связаны с циклом.
- Для активного цикла задан ровно один главный старт. Дополнительных
  стартов может быть несколько. Перенос или замена главного старта
  оформляется новой версией, а не переписыванием истории.
- В первой версии приложения у одного аккаунта не более одного активного
  цикла; черновые, завершённые и отменённые циклы сохраняются отдельно.
- На весь цикл можно задать этапы и недельные ориентиры без точного
  расписания. Ближайшие недели детализируются по мере необходимости.
- Неделя имеет уровень детализации: `outline` или `scheduled`.
  Отсутствие занятий в `outline` не означает отдых или нулевой объём.
- Для занятия задаётся степень определённости: `tentative` или `fixed`.
  Она не заменяет сведения о выполнении или публикации в Garmin.
- Несколько занятий в один день допустимы. Явный день отдыха отличается
  от дня, для которого план ещё не составлен.

## 4. Хранение и модель данных

Источник истины — существующая локальная база `garmin.sqlite3`.
Markdown и экспортируемые файлы служат представлениями, а не параллельными
редактируемыми копиями плана. Схема добавляется номерными миграциями.

Все сущности принадлежат `account_id`; ссылки между аккаунтами запрещены.
Локальные идентификаторы не зависят от Garmin. У сущностей плана есть
стабильный ID, сохраняющийся при переносе и редактировании занятия.

### Сущности

| Таблица / группа | Содержание |
| --- | --- |
| `training_cycles` | Стабильный ID цикла, аккаунт, указатель текущей принятой версии, время создания |
| `plan_revisions` | Номер и ID версии, родительская версия, статус, автор, время, причина, ссылки на использованные данные |
| `cycle_versions` | Название, статус цикла, начало и конец, часовой пояс, главный старт, цель и принципы подготовки в данной версии |
| `event_versions` | ID мероприятия, название, дата, часовой пояс, дистанция, набор высоты, роль, статус участия, цель и примечание |
| `constraint_versions` | ID условия, период действия, доступные дни, бюджет времени, предпочтения и ограничения |
| `phase_versions` | ID этапа, даты, название, задача и пояснение |
| `week_versions` | Начало недели, этап, уровень детализации, целевые диапазоны объёма и времени, акценты недели |
| `session_versions` | ID занятия, неделя, дата, порядок в дне, вид, назначение, целевые значения, варианты и структура выполнения |
| `session_outcomes` | Оценка выполнения стабильного ID занятия, ссылка на версию задания, ручные фактические значения, причина отклонения |
| `activity_matches` | Связи занятий с существующими `activities`, состояние сопоставления, основание и распределение фактических значений |
| `training_feedback` | Дата, необязательная ссылка на занятие, субъективное усилие, самочувствие, комментарий |
| `training_reviews` | Период обзора, версия плана, использованные источники, выводы и связь с предложенной версией |
| `garmin_publications` | Занятие и его версия, отправленный payload и его хеш, идентификаторы Garmin, дата назначения, результат и ошибки |

### Поля и единицы

- Скаляры хранятся типизированными столбцами. Длительности — секунды,
  дистанции — метры, набор высоты — метры, темп — секунды на километр,
  пульс — удары в минуту. Для диапазонов используются нижняя и верхняя границы.
- Неизвестное значение — `NULL`, а не ноль. Диапазоны должны быть
  упорядочены, значения расстояния и длительности — неотрицательны.
- Цель цикла и старта: тип (`finish`, `target_time`, `other`), целевое
  время при наличии и текстовое описание. Для `target_time` время обязательно.
- Роль мероприятия: `main`, `secondary`, `training`.
  Статус участия: `considering`, `planned`, `registered`, `completed`, `cancelled`.
  Главный старт активного цикла должен иметь известную дату и не быть отменён.
- Вид занятия: лёгкий бег, длительный бег, интервалы, темповое занятие,
  соревнование, силовая, другая активность или отдых. Вид занятия и вид
  спорта хранятся отдельно; непредставимые в Garmin занятия остаются локальными.
- Структурированное задание сохраняется как JSON с версией схемы;
  для совместимых занятий используется существующий `WorkoutSpec`.
  Повторяющиеся интервальные блоки не требуют отдельных SQL-строк.
- Варианты занятия могут храниться вложенными данными. Выбранный вариант
  фиксируется явно; альтернативы не суммируются в недельный объём.
- Недельные ориентиры и сумма детализированных занятий показываются
  отдельно. Неизвестная дистанция занятия по времени не подменяется
  выдуманной оценкой; оценки должны иметь явную пометку и основание.
- У ограничений и недельных ориентиров есть необязательный вид спорта;
  без него сохраняется общий учёт. Отчёты разделяют бег, велосипед и другие
  занятия; общий итог времени показывается дополнительно. Ручное выполнение
  относится к спорту исходного задания. Замена беговой длинной велосипедом
  отменяет исходное задание и создаёт связанное велосипедное занятие.
- Субъективное усилие — необязательное целое число от 1 до 10.
  Самочувствие и причины отклонений доступны без записи Garmin.

### Даты

- Дата занятия — локальная календарная дата, время начала необязательно.
  Часовой пояс сохраняется явно; исходный берётся из настроек приложения.
- У мероприятий может быть собственный часовой пояс. Изменение часового
  пояса устройства не сдвигает автоматически даты плана.
- Неделя начинается в понедельник. При сопоставлении с Garmin учитывается
  временной контекст активности; одной даты недостаточно для подтверждения.
- Время создания, изменения, публикации и расчёта хранится в UTC.

## 5. Версии и история

- Версия содержит полный снимок плановых данных: цели, мероприятия,
  ограничения, этапы, недели и занятия. Для личного плана допустимо
  копирование этих строк; отдельная система событий не требуется.
- Ключ строки снимка включает `revision_id` и стабильный ID сущности.
  Ссылки внутри снимка проверяются в пределах одной версии и аккаунта.
- Состояния версии: `draft`, `accepted`, `superseded`, `discarded`.
  Содержимое принятой или заменённой версии неизменно.
- Первая принятая версия служит исходным планом. Доступны сравнения
  «исходный — текущий» и «предыдущий — предложенный».
- Каждая мутация передаёт ожидаемую текущую версию. Принятие нового
  снимка и смена указателя цикла выполняются одной транзакцией.
  При конкурирующем изменении возвращается `conflict`; данные не затираются.
- Прямое поручение пользователя изменить локальный план или действие
  «Сохранить» в интерфейсе достаточно для применения. Дополнительное
  подтверждение каждого локального изменения не требуется.
- Не запрошенные пользователем рекомендации агента сохраняются черновиком
  с понятным сравнением; текущий план до применения остаётся прежним.
- Перенос сохраняет ID занятия. Замена другим занятием создаёт новый ID
  со ссылкой `replaces_session_id`; старое сохраняется в истории.
- После начала выполнения задание привязывается к конкретной принятой
  версии через результат или подтверждённое сопоставление. Последующая
  корректировка плана не меняет задним числом основание оценки выполнения.
- Обратная связь, сопоставления и публикации живут отдельно от снимков.
  Их исправления журналируются с прежним и новым значением, автором и причиной.
- Отмена занятия сохраняет его в текущем снимке с состоянием `cancelled`.
  Отмена и удаление черновика не удаляют активности Garmin или историю.
- Возврат к прежнему плану создаёт новую версию на его основе; он не
  откатывает фактические данные и не выполняет операции в Garmin.

## 6. План и фактическое выполнение

- Плановое задание, зарегистрированная активность и оценка выполнения —
  разные сущности. Garmin не перезаписывает плановые значения.
- Сопоставление поддерживает несколько активностей на занятие и несколько
  занятий на активность, например отдельные записи разминки и интервалов.
- Состояния связи: `suggested`, `confirmed`, `rejected`, `needs_review`.
  Кандидаты подбираются по дате, спорту, длительности, дистанции и доступным
  идентификаторам; основание предложения показывается пользователю.
- Только подтверждённые связи входят в сравнение по занятиям. Пользователь
  может подтвердить, отклонить или исправить связь через любой интерфейс.
- Если одна активность отнесена к нескольким занятиям, задаётся явное
  распределение времени/дистанции или непересекающихся сегментов. До этого
  сравнение отдельных занятий считается неполным. Двойной учёт запрещён.
- Фактический объём недели считается по уникальным активностям независимо
  от сопоставления; внеплановые занятия показываются отдельно. Ручные записи
  включаются как отдельные факты, только если не дублируют импортированные.
- Когда появляется Garmin-запись для ручного выполнения, пользователь
  связывает её с записью и выбирает источник показателей; комментарий сохраняется.
- Статусы выполнения: `unknown`, `completed`, `partial`, `skipped`.
  Прошедшая дата без активности остаётся `unknown`; пропуск отмечается явно.
  Отмена относится к плану и не равна пропуску.
- Для отдыха учитывается отметка соблюдения плана без создания активности
  и без добавления нулевого занятия в статистику тренировок.
- Исправление источника Garmin помечает затронутые сопоставления и обзоры
  как требующие пересмотра. Подтверждённая история не переписывается молча.
- Обзор показывает покрытие и свежесть источников. Недоступные сон, HRV
  или другие показатели не интерпретируются как нормальные или нулевые.

## 7. Архитектура и операции

```text
Чат / MCP ───────┐
                ├─ Сервис планирования ─ SQLite
Веб / HTTP ──────┘          │                ↑
                           │         Существующий импорт Garmin
                           ↓
                  Предпросмотр и публикация в Garmin
```

- Добавить модуль планирования в существующий Python-пакет. Разделить
  модели, хранение снимков, правила изменений, сопоставление и публикации.
- HTTP и MCP вызывают общий сервис; интерфейсы не реализуют собственные
  правила версионирования или записи в базу.
- Сервис проверяет принадлежность аккаунту, ссылки, даты, единицы,
  структуру интервалов, ожидаемые версии и допустимые переходы состояний.
- Противоречия расписанию и недельным ориентирам показываются как
  предупреждения. Применение вопреки ограничению сохраняет объяснение.
- При выходе занятия за границы цикла или недели требуется согласованное
  изменение дат/принадлежности в том же снимке; потерянные ссылки запрещены.
- Агент получает компактный контекст: цель, мероприятия, ограничения,
  выбранный период плана, фактические данные, обратную связь, решения
  и полноту источников. Контекст читается из базы без скрытой загрузки Garmin.
- Чтение календаря не запускает импорт или пересчёт признаков.
  Пересчёт показателей и подбор соответствий выполняются явными запросами.
- Все сервисы остаются локальными. Автоматически выполняется только
  существующее резервное копирование, если оно включено.

Минимальный набор операций с одинаковыми возможностями в MCP и HTTP:

| Группа | Операции |
| --- | --- |
| Циклы | Создать, получить, перечислить, завершить или отменить |
| План | Получить диапазон дат, создать/редактировать черновик, сравнить версии, применить, отбросить |
| Контекст | Получить цель, условия, историю решений и качество исходных данных |
| Выполнение | Найти кандидатов, подтвердить/отклонить связь, записать ручное выполнение, исправить распределение |
| Обратная связь | Добавить/исправить усилие, самочувствие и комментарий |
| Обзор | Получить план/факт, сохранить выводы и ссылки на предложенные изменения |
| Garmin | Предпросмотр публикации, публикация, проверка результата и разрешённый повтор |

HTTP использует префикс `/api/training`; модели и ошибки документируются
в OpenAPI. Изменения принимают `expected_revision_id` или версию изменяемой
операционной записи. Для повторяемых команд создания и применения
используется ключ идемпотентности; повтор возвращает прежний результат,
а тот же ключ с другим содержимым возвращает конфликт.

Ответы явно различают `validation_error`, `not_found`, `conflict`,
`missing_inputs`, `partial` и ошибки внешнего сервиса. Неудачная публикация
не отменяет уже сохранённый локальный план.

## 8. Публикация в Garmin

- Локальное сохранение плана не отправляет ничего в Garmin.
- Публикуются только выбранные совместимые занятия после предпросмотра
  и явного подтверждения Garmin-записи (`confirm=true`).
- Публикация ссылается на точную версию занятия, дату и отправленный payload.
  Изменённый после предпросмотра payload требует нового предпросмотра.
- Разделять состояния: `not_published`, `in_progress`, `created`,
  `scheduled`, `failed`, `unknown`, `outdated`, `removed`.
  Сохранять этап операции, идентификаторы и текст ошибки.
- При успехе создания и ошибке назначения сохраняется ID созданной
  тренировки. Повтор назначения использует его и не создаёт новую тренировку.
- Если ответ потерян и результат неизвестен, не повторять создание
  автоматически. Сначала по запросу проверить Garmin; при невозможности
  однозначной проверки сообщить о неопределённости.
- Изменение уже опубликованного занятия помечает публикацию `outdated`.
  Замена, перенос или удаление в Garmin — отдельные явно подтверждённые
  действия. Отсутствие поддержки операции не скрывается.
- Локальная идемпотентность предотвращает повтор известных операций,
  но не обещает гарантию однократной записи со стороны Garmin.
- Статус `scheduled` означает подтверждённое назначение в Garmin Connect;
  доставку и отображение на часах приложение не считает подтверждёнными.

## 9. Интерфейс

### Сегодня и неделя

- Задания по дням, назначение каждого, целевые диапазоны и структура.
- Явное различие отдыха, отсутствующего плана и неизвестного выполнения.
- Рядом с планом — факт, источник данных, отметка усилия и комментарий.
- Перенос, отмена, выбор варианта и ручная отметка выполнения.
- Перенос опубликованного занятия показывает необходимость обновить Garmin.

### Подготовка целиком

- Главный старт, цель, дополнительные мероприятия и этапы подготовки.
- Недельные ориентиры, сумма запланированных занятий и фактический объём.
- Видимость приблизительных недель, ограничений и полноты данных.
- Переход к календарю выбранной недели и истории версий.

### Обзор недели

- Выполненные, частично выполненные, пропущенные и внеплановые занятия;
  неизвестное выполнение выделяется отдельно.
- Отклонения по времени/дистанции и обратная связь пользователя.
- Выводы агента с основаниями и предложенное изменение в формате
  «было — стало — причина»; применение одним действием.
- Обзор не требует доступности всех метрик Garmin; ограничения анализа
  отображаются вместе с выводами.

## 10. Надёжность и резервное копирование

- Миграции атомарны; существующие активности, источники и признаки сохраняются.
- Плановые снимки, обратная связь, обзоры, связи и публикации включаются
  в существующий SQLite backup и проверку восстановления.
- Восстановление не выполняет Garmin-записей. Сохранённые публикации
  после восстановления требуют сверки с текущим внешним состоянием
  перед последующими изменениями в Garmin.
- Основные операции фиксируются в журнале с автором, временем, причиной
  и идентификаторами версий; секреты и токены туда не попадают.
- Ручной ремонт данных выполняется транзакционно с сохранением истории
  и проверкой тех же ограничений; обычные правки проходят через сервис.

## 11. Этапы реализации

### Первая версия: ежедневное использование

- Цикл, мероприятия, условия, этапы, недели и занятия в SQLite.
- Полные снимки, сравнение версий и защита от конкурирующих изменений.
- Общие операции через HTTP/MCP; календарь недели и обзор цикла.
- Ручное выполнение, обратная связь и ручное сопоставление с Garmin.
- Базовый план/факт без двойного учёта и с указанием полноты данных.
- Резервное копирование и восстановление новых сущностей.
- Существующие инструменты создания Garmin-тренировок сохраняются;
  управляемая публикация из плана в этот этап не входит.

### Следующий этап: анализ и публикация

- Предложения сопоставлений и сохраняемые обзоры недели с выводами агента.
- Подготовка черновиков изменений на основе выполнения и новых мероприятий.
- Публикация выбранных занятий, учёт версий и обработка частичных ошибок.
- Экспорт календаря или отчёта можно добавить отдельно при необходимости.

## 12. Критерии приёмки

Первая версия считается готовой, когда проверены следующие сценарии:

1. Цикл с главным и дополнительным стартами сохраняется и доступен
   после перезапуска через HTTP, MCP и календарь с одинаковыми значениями.
2. Дополнительное мероприятие можно добавить согласованным изменением
   расписания; предыдущая версия и причина изменения остаются доступны.
3. Перенос сохраняет ID занятия; сравнение версий показывает старую
   и новую даты. Конкурирующая правка возвращает конфликт без потери данных.
4. Фактическая дистанция не меняет плановую. Ручное выполнение работает
   без Garmin и не дублируется после привязки импортированной активности.
5. Разминка и основная часть могут соответствовать одному заданию;
   разделённая между заданиями активность учитывается без двойного объёма.
6. День без загруженных данных не объявляется пропущенным, а неделя
   без детального расписания не отображается как нулевой план.
7. Поздняя корректировка сохраняет исходное задание, по которому было
   оценено выполнение; история обратной связи остаётся доступной.
8. Ограничение на период поездки видно при планировании; часовые пояса
   и граница недели не приводят к неявному сдвигу даты занятия.
9. Чтение экранов не обращается к Garmin. При неполных источниках
   сравнение показывает ограничения, а не подставляет нулевые значения.
10. Backup/restore восстанавливает план, версии, связи и заметки;
    восстановление не отправляет Garmin-команд.

Для следующего этапа дополнительно проверяются:

11. Предложение агента сохраняется черновиком; его применение фиксирует
    использованные данные, причину и новую версию плана.
12. Ошибка назначения после создания Garmin-тренировки допускает повтор
    назначения по сохранённому ID без повторного создания.
13. Потерянный ответ Garmin оставляет состояние `unknown`; изменение
    задания помечает старую публикацию `outdated`; ни одно из этих
    состояний не вызывает автоматической повторной записи.

Проверки выполняются на локальных фикстурах и подменённом Garmin gateway.
Реальные Garmin-записи не входят в автоматические тесты. Перед регулярным
использованием публикации отдельно проверяется простое занятие в Garmin
Connect и на конкретных часах после подтверждения пользователя.
